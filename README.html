1. 한눈에 보기

1.1 무엇인가요?

Herdr(허더)는 터미널(검은 명령 창)을 여러 개 한 화면에 모아 보여 주는 프로그램입니다. 터미널 안에서 Claude Code나 Codex 같은 AI 도우미와 대화하며 일하는 분이 많습니다.

문제는 이럴 때 생깁니다.

  • 컴퓨터를 껐다 켜면 Herdr 의 창은 빈 터미널로 돌아오고, 하던 AI 대화는 끝나 있습니다. (대화 기록은 파일로 남아 있지만, 어느 창에서 어느 대화를 하고 있었는지는 사람이 기억해야 합니다.)
  • Herdr 를 계속 켜 둔 채로는 앱 업데이트가 영영 적용되지 않습니다. (원인과 해결은 11. 업데이트 내용 요약에 있습니다.)

세션키퍼는 이 두 가지를 해결합니다.

기능쉽게 말하면자동/수동
세션 기억1분마다 "어느 창에서 어느 AI 대화를 하는지"를 메모해 둡니다.자동
세션 복구Herdr 를 다시 켜면 메모를 보고 claude --resume <대화번호> 또는 codex resume <대화번호> 를 그 창에 입력해 대화를 이어 줍니다.자동 + 수동(버튼)
세션키퍼 창Herdr 안에서 Ctrl+Shift+R 을 누르면 열리는 목록 창. 복구할 대화를 눈으로 보고 골라 복구합니다.수동
앱 자동 업데이트Herdr 가 열려 있어도 새 버전을 안전하게 적용합니다. 실패하면 전부 원래대로 되돌립니다. 끄고 켤 수 있습니다.자동(끌 수 있음) + 수동

1.2 하지 않는 일 (오해 방지)

  • 인터넷으로 아무것도 보내거나 받지 않습니다. 이 도구의 코드에는 인터넷 접속 부분이 없습니다(15장 참고).
  • AI 대화의 내용을 복원하지는 않습니다. 대화 기록 파일을 이어서 여는 것입니다. 컴퓨터가 꺼질 때 AI 가 하던 "한 번의 작업"은 이어지지 않습니다.
  • AI 세션 안에서 켜 둔 감시(Monitor)·예약(ScheduleWakeup/Cron) 은 되살리지 않습니다(알려 주기만 합니다).
  • 컴퓨터를 저절로 켜 주지 않습니다. 부팅만으로는 아무것도 켜지지 않고, 사용자가 Herdr 를 켜야 동작합니다.
  • 직접 닫은 창은 되살리지 않습니다(사고로 닫힌 창만 대상입니다).

1.3 누구에게 필요한가요?

Windows 에서 Herdr 를 쓰면서 Claude Code 또는 Codex 로 여러 작업을 동시에 하는 분. 한두 개 창만 쓴다면 필요성이 낮습니다.

3. 사전 준비물과 필요 프로그램

3.1 반드시 필요한 것

필요한 것왜 필요한가확인 방법없으면
Windows 10/11 (64비트)이 도구는 Windows 전용입니다.개발·시험은 Windows 11 Home 10.0.26300 에서만 했습니다. Windows 10 은 미확인입니다.다른 OS 는 지원하지 않습니다.
Windows PowerShell 5.1본체 스크립트 실행Windows 에 기본 포함. 시험 버전 5.1보통 이미 있습니다.

Node.js 18 이상목록·복구 도구 실행터미널에 node --version 입력. 시험 버전 v26.7.04.2
쓸 수 있는 폴더설치 위치(기본 %LOCALAPPDATA%\HerdrSessionKeeper\app)보통 가능다른 위치를 -InstallDir 로 지정

3.2 있으면 좋은 것 (선택)

선택 프로그램용도
Claude CodeClaude 대화를 복구하려면 필요(복구는 claude --resume 을 실행).

3.3 설치 전에 정해 두면 좋은 것

  • 설치 위치를 바꾸고 싶은지(기본값이면 아무것도 안 해도 됩니다).
  • 자동 업데이트를 켜 둘지(기본 켜짐). 나중에 언제든 바꿀 수 있습니다.
  • 작업 스케줄러 등록을 허용할지(허용하지 않으면 Herdr 를 켜도 키퍼가 저절로 켜지지 않아 수동 실행이 필요합니다. 옵션 -NoTask).

3.4 권한

  • 관리자 권한이 필요 없습니다. 현재 로그인한 사용자 계정에만 설치됩니다.
  • 회사 PC 처럼 작업 스케줄러 등록이나 스크립트 실행이 제한된 환경에서는 설치 중 경고가 나올 수 있습니다(16장).

4. 다운로드 방법

현재 상태(2026-11-26 확인): 이 꾸러미는 GitHub 저장소 https://github.com/sodam-ai/SoDam-Herdr-Session-Keeper 에 공개되어 있습니다. 아래 4.3 의 방법으로 받으세요.

4.1 Herdr 받기

  • Herdr 공식 저장소: https://github.com/herdrdev/herdr — 설치 방법은 그곳의 안내를 따르세요.
  • 설치 뒤 한 번 실행해 두세요(설정 폴더 %USERPROFILE%\.config\herdr-app 가 만들어져야 세션키퍼를 설치할 수 있습니다).
  • 확인: 시작 메뉴에서 Herdr 를 열 수 있고, 일반 위치에 설치했다면 %LOCALAPPDATA%\Programs\herdr-app\herdr-app.exe 파일이 있습니다.

4.2 Node.js 받기

  1. 웹 브라우저로 https://nodejs.org 에 갑니다.
  2. LTS 라고 적힌 설치 파일을 받아 실행하고, 안내대로 "다음"을 눌러 끝까지 설치합니다.
  3. 새 터미널을 열고 node --version 을 입력해 v18 이상 숫자가 나오는지 확인합니다. (설치 직후 열려 있던 터미널은 새 설치를 모를 수 있어 새로 열어야 합니다.)
  4. 참고: winget(Windows 패키지 관리자)이 있는 PC 라면 그것으로도 설치할 수 있다고 알려져 있으나, 개발 PC 에는 winget 이 없어 확인하지 못했습니다.

4.3 세션키퍼 꾸러미 받기

저장소 최상위에 .claude-plugin(마켓플레이스 목록)과 plugins\herdr-session-keeper(설치 꾸러미)가 들어 있습니다. 설치 프로그램은 plugins\herdr-session-keeper\install.cmd 입니다.

  1. 저장소 페이지의 초록색 Code 버튼 → Download ZIP 으로 받거나, git 이 있다면 git clone https://github.com/sodam-ai/SoDam-Herdr-Session-Keeper.git 을 실행합니다.
  2. 받은 폴더(또는 ZIP 파일)를 설치할 PC 에 옮깁니다(같은 PC 에서 받았다면 건너뜁니다).
  3. 설치할 PC 에서 압축을 완전히 풉니다. (압축 파일 안에서 바로 실행하면 안 됩니다. payload 폴더를 찾지 못해 "설치 파일이 없습니다" 로 멈춥니다.)
  4. 폴더 경로에 한글·공백이 있어도 동작하도록 시험했지만, 가능하면 영문 경로를 권장합니다.

설치 꾸러미를 직접 다시 만들려면(개발자용): 프로젝트 폴더에서 node build-kit.mjs (10.7 참고).

5. 설치 방법

설치 방법은 두 가지입니다. 방법 2(더블클릭)가 가장 쉽습니다.

먼저 어느 방법이든 점검만 해 볼 수 있습니다. 점검은 아무것도 바꾸지 않습니다(5.3).

5.1 방법 1 — Claude Code 마켓플레이스로 설치

Claude Code 에서 아래 두 줄을 한 줄씩 입력합니다. 이 저장소가 그대로 마켓플레이스입니다.

/plugin marketplace add sodam-ai/SoDam-Herdr-Session-Keeper
/plugin install herdr-session-keeper@herdr-session-keeper-market

그다음 Claude 에게 "세션키퍼 설치해줘" 라고 말하면, 들어 있는 스킬이 점검 → 바뀌는 내용 설명 → 확인 → 설치 순서로 진행합니다.

미확인: 이 두 명령을 실제 Claude Code 에서 끝까지 실행해 본 적은 없습니다. 꾸러미 형식 검사(claude plugin validate)만 통과했습니다. 문제가 있으면 방법 2 를 쓰세요.

5.2 방법 2 — 직접 설치 (더블클릭)

  1. 꾸러미 폴더 안 plugins\herdr-session-keeper\install.cmd 를 더블클릭합니다.
  2. 검은 창에 진행 상황이 나옵니다(6단계). 끝나면 "설치가 끝났습니다."가 나옵니다.
  3. 아무 키나 눌러 창을 닫습니다.

터미널에서 직접 실행하려면:

powershell -NoProfile -ExecutionPolicy Bypass -File plugins\herdr-session-keeper\install.ps1

5.3 설치 전 점검 (추천)

powershell -NoProfile -ExecutionPolicy Bypass -File plugins\herdr-session-keeper\install.ps1 -Check

Node.js·Herdr·설정 폴더·다른 위치의 기존 설치를 확인만 하고 끝납니다. "점검 완료: 설치할 수 있는 환경입니다"가 나오면 준비가 된 것입니다. "중단:" 으로 시작하는 줄이 나오면 그 이유를 해결한 뒤 다시 하세요.

5.4 설치가 하는 일 (6단계)

단계하는 일
1/6 환경 점검Node.js 18+, Herdr 앱, hc, Herdr 설정 폴더를 찾습니다. 다른 위치에 이미 설치된 세션키퍼가 있는지 봅니다.
2/6 프로그램 복사프로그램 파일을 설치 위치로 복사하고(이전 설치가 있으면 한 벌 백업, 최근 3벌 보관), 찾은 위치들을 kit.env 에 적습니다.
3/6 Herdr 모드mods\session-keeper 에 화면 파일 3개를 복사하고 설치 위치·node 경로를 채워 넣은 뒤 Herdr 공식 검사(herdr-app check)를 돌립니다.
4/6 키 연결keys.json 에 Ctrl+Shift+R 한 줄을 추가합니다(원본 백업 keys.json.bak-before-session-keeper-kit). -NoKey 를 주었거나 keys.json 이 없으면 이 단계를 건너뛰고, 추가한 결과가 올바른 JSON 이 아니면 파일에 쓰지 않습니다. 고른 키를 Herdr 가 이미 다른 기능에 쓰고 있으면 그 줄만 건너뛰고 설치는 계속합니다(Ctrl+Shift+P 로 열 수 있습니다).
5/6 자동 실행 작업작업 스케줄러에 HerdrSessionKeeper-Watchdog 를 만듭니다(1분마다, Herdr 가 켜져 있을 때만 키퍼를 켬).
6/6 마무리설치 기록(kit.install.json)을 쓰고, 자동 실행 작업이 등록됐고 Herdr 가 켜져 있으면 감시를 즉시 한 번 호출합니다(-NoTask 이거나 작업 등록에 실패하면 호출하지 않습니다).

5.5 설치 옵션

옵션의미

-HerdrHome <경로>Herdr 설정 폴더(기본: 환경변수 HERDR_APP_HOME, 없으면 %USERPROFILE%\.config\herdr-app)
-HerdrApp <경로>herdr-app.exe 위치(자동 탐색이 실패할 때)
-TaskName <이름>작업 스케줄러 작업 이름(기본 HerdrSessionKeeper-Watchdog)

-NoKey단축키 연결 안 함(대신 Ctrl+Shift+P → mod.open session-keeper)

-RestartKeeper이미 돌고 있는 키퍼를 끄고 새 코드로 다시 시작(1분 안에 감시가 다시 켬)

5.6 이미 세션키퍼가 설치되어 있다면

다른 위치에 설치된 작업(작업 스케줄러)이나 모드가 있으면 설치는 덮어쓰지 않고 멈춥니다("중단: … 덮어쓰지 않았습니다"). 기존 것을 계속 쓰거나, 이 설치로 바꾸려면 -Force 를 붙이세요(기존 작업·모드가 이 설치를 가리키도록 바뀝니다). 같은 위치에 다시 설치(업데이트)하는 것은 그냥 됩니다.

5.7 환경·폴더·컴퓨터가 달라도 동작하는 방법

아래 위치는 그 PC 에서 자동으로 찾습니다(경로가 코드에 박혀 있지 않습니다). Node·hc 는 설치할 때 찾아 kit.env 에 적고, Herdr 앱·Herdr 설정 폴더는 기본 위치가 아닐 때만 적으며, Claude·Codex 대화 폴더는 프로그램이 실행될 때마다 찾습니다.

찾는 것순서
Node.jsPATH → %ProgramFiles%\nodejs 등 흔한 위치 (18 이상만 인정)
Herdr 앱-HerdrApp → 환경변수 KEEPER_APP_EXE → %LOCALAPPDATA%\Programs\herdr-app → PATH → 설치 목록(레지스트리)
hc (herdr-core)PATH → 앱 옆 herdr-core → %LOCALAPPDATA%\Programs\herdr-core
Herdr 설정 폴더-HerdrHome → 환경변수 HERDR_APP_HOME → %USERPROFILE%\.config\herdr-app
Claude 설정 폴더환경변수 CLAUDE_CONFIG_DIR → %APPDATA%\claude-code(있을 때) → %USERPROFILE%\.claude
Codex 데이터환경변수 CODEX_HOME 이 있으면 그 폴더. 없으면 %USERPROFILE%\.codex_runtime 과 %USERPROFILE%\.codex 중 상태 파일이 더 최근에 쓰인 한 곳

폴더를 옮기려면 새 위치에 -InstallDir 새위치 로 다시 설치하세요. 옛 위치에 파일이 이미 없다면(옮기거나 지운 경우) 설치 프로그램이 "폴더를 옮기신 것으로 보입니다"라고 알리고 -Force 없이 새 위치로 다시 연결합니다. 옛 위치가 아직 그대로 있으면(복사만 한 경우) 다른 설치로 보고 멈추므로, 옛 위치를 uninstall.ps1 -InstallDir 옛위치 로 지우거나 -Force 를 붙이세요. 옛 위치의 드라이브 자체가 없으면(외장 디스크가 빠졌을 수 있어) 안전하게 멈춥니다. 폴더를 옮기고 다시 설치하지 않으면 1분마다 도는 복구 예약 작업이 옛 위치를 가리켜 실패하고 키퍼가 켜지지 않습니다(실측).

5.8 단축키 바꾸기

세션키퍼 창은 기본으로 Ctrl+Shift+R 로 엽니다. 창 안에서는 맨 윗줄의 [단축키] 버튼을 누르세요. 후보 키를 누르거나, 입력칸에 원하는 키를 쓰고 적용을 누르거나, [직접 누르기] 후 원하는 키 조합을 누르면 됩니다. 다른 기능과 겹치는 키는 거절하고, 확인 버튼을 한 번 더 눌러야만 그 기능을 해제하고 덮어씁니다. 명령어로 바꾸려면 설치된 폴더의 set-key.ps1 을 쓰세요(설치할 때 -Key 로 처음부터 정해도 됩니다).

powershell -NoProfile -ExecutionPolicy Bypass -File "%LOCALAPPDATA%\HerdrSessionKeeper\app\set-key.ps1" -Show
powershell -NoProfile -ExecutionPolicy Bypass -File "%LOCALAPPDATA%\HerdrSessionKeeper\app\set-key.ps1" -Key ctrl-alt-r
powershell -NoProfile -ExecutionPolicy Bypass -File "%LOCALAPPDATA%\HerdrSessionKeeper\app\set-key.ps1" -Reset
옵션하는 일
-Show지금 연결된 키를 알려 줌(아무것도 바꾸지 않음)
-Key <키>그 키로 바꿈. ctrl-alt-r 처럼 써도 되고 Ctrl+Alt+R 처럼 써도 됨
-Reset기본 키 Ctrl+Shift+R 로 되돌림
-Replace바꾸려는 키를 이미 다른 기능이 쓰고 있을 때, 그 기능의 연결 한 줄만 해제하고 세션키퍼에 연결(원본은 백업)
-Remove단축키 연결만 끔(팔레트 Ctrl+Shift+P → mod.open session-keeper 로는 계속 열 수 있음)
-DryRun쓸 수 있는 키인지만 확인하고 아무것도 쓰지 않음
-HerdrHome <경로>Herdr 설정 폴더를 직접 지정(설치된 폴더에서 실행하면 kit.env 의 위치를 자동으로 씀)

안전 규칙은 이렇습니다.

  • 바꾸려는 키를 Herdr 가 이미 다른 기능에 쓰고 있으면 기본은 바꾸지 않고, 어떤 기능과 겹치는지 알려 줍니다. -Replace(창에서는 [덮어쓰기]를 두 번 누름)를 써야만 그 한 줄을 해제합니다.
  • 쓸 수 있는 키: 조합 키(ctrl, alt, shift)에 영문·숫자·기호(, . / [ ] 등)·f1-f12·방향키·pageup·tab·space 등을 붙인 것. F1~F12 는 혼자 써도 됩니다. Ctrl+Alt+K, ctrl-alt-k 처럼 어떻게 써도 됩니다.
  • 터미널 필수 키(Ctrl+C, Ctrl+D, Ctrl+Z)와 Ctrl·Alt 없는 글자 키는 거부합니다. 다른 Ctrl+글자 는 허용하지만, 연결하면 터미널 안에서는 그 키가 동작하지 않는다고 알려 줍니다.
  • 고친 결과가 올바른 JSON 이 아니면 파일을 그대로 두고 멈춥니다. 처음 한 번은 원본을 keys.json.bak-before-session-keeper-kit 로 백업합니다.
  • 다시 설치(업데이트)해도 -Key 를 주지 않으면 바꾼 키를 그대로 유지합니다. 제거(uninstall.ps1)는 바꾼 키도 함께 지웁니다.
  • 바꾼 뒤 Herdr 가 바로 인식하지 않으면 Herdr 를 한 번 껐다 켜세요. (Herdr 가 keys.json 을 바로 다시 읽는지는 확인하지 못했습니다.)

  1. Node.js 설치(4.2) 후 새 터미널에서 node --version 확인.
  2. Herdr 설치 후 한 번 실행(4.1).
  3. 꾸러미 폴더를 옮기고 압축을 풉니다(4.3).

7. 실행 방법 (켜기·끄기)

7.1 평소에는 아무것도 안 해도 됩니다

  • 작업 스케줄러가 1분마다 "Herdr 가 켜져 있나?"를 봅니다.

[앱 업데이트]파일을 안전하게 교체하고 Herdr 창만 껐다 켭니다(터미널은 herdr-core 가 유지). 두 번 눌러야 실행. 창이 잠깐 닫혔다 열립니다.
[자동 업데이트: 켜짐/꺼짐]자동 적용을 켜고 끕니다(기본 켜짐). 이 버튼은 업데이트 줄 안에 있어서 평소(최신이고 자동 켜짐)에는 보이지 않으며, 그때 끄려면 -Mode Update -Auto Off 를 씁니다. 끄면 session-keeper.appupdate.off 파일이 생깁니다.

두 버튼이 가까이 있으니 누를 때 화면을 확인하세요. 개발 PC 에서 한 번, 업데이트와 "자동 업데이트 꺼짐"이 같은 초에 기록된 일이 있었습니다(원인 미확정, 버튼 위치 이동 가능성). 의도와 다르면 -Mode Update -Auto On 으로 다시 켜세요.

자동 적용 시점(자동 업데이트가 켜져 있을 때):

  1. Herdr 가 켜진 지 3분 이내에 키퍼가 옛 버전을 발견하면 바로 적용합니다. 오래 켜 둔 창은 저절로 껐다 켜지 않고 알림만 합니다.
  2. (선택) 런처를 설치했다면 앱이 켜지기 전에 적용합니다.
  3. (선택) session-keeper.appupdate.idle 파일을 만들면 앱이 켜진 채 한가할 때도 적용합니다(기본 꺼짐).

런처(선택): session-keeper.ps1 -Mode Update -Launcher Install — 바탕화면·시작 메뉴 바로가기를 런처에 연결하고 시작 위치를 사용자 폴더로 고칩니다(Herdr 설치 폴더가 시작 위치면 업데이트가 막히는 것이 근본 원인이기 때문, 11장). 작업표시줄 고정 아이콘은 시작 위치만 고칩니다. 원본 바로가기는 shortcut-backup\ 에 백업되며 -Launcher Uninstall 로 되돌립니다. 런처가 실패해도 Herdr 는 반드시 켜집니다. 실제 바로가기에 설치해 본 적은 없습니다(미확인, 19장).

9. 작동 방법 (어떤 원리로 동작하나)

9.1 평소 (1분마다): 기억하기

키퍼가 Herdr 코어(hc ls)에서 열린 창 목록을 읽고, 각 창에서 돌고 있는 AI 대화의 번호를 알아내 session-map.json 에 적습니다.

  • Claude: Claude Code 가 남기는 실행 중 세션 파일과 프로세스 계보(세션 → 부모 … → 창의 셸)로 어느 창인지 정확히 연결합니다.
  • Codex: 아래 순서로 확정합니다. 확실하지 않으면 기록하지 않고 이유를 로그에 남깁니다(틀린 대화를 이어 붙이는 것보다 낫기 때문).
    1. 명령줄의 codex resume <ID> (키퍼가 복구한 창은 전부 이 방식이라 정확).
    2. 같은 작업 폴더 + 창이 켜진 뒤 갱신된 대화 파일.
    3. 같은 폴더에 Codex 창이 둘 이상이면 화면 대조: 후보 대화의 최근 발화 앞 40자(공백 무시)가 어느 창 화면(hc read)에 보이는지 비교해, 창 하나가 후보 하나와만 맞고 그 후보도 다른 창과 겹치지 않을 때만 확정.
  • 창 자체가 사라진 경우: 같은 Herdr 가 계속 떠 있고 종료 이유가 killed(탭·공간을 직접 닫음)이면 "직접 닫음"으로 보고 복구 목록에서 바로 뺍니다. 그 밖(코어 재시작·앱 전체 종료·종료 기록 없음·30초 안에 6개 이상 동시 종료)은 사고나 불확실로 보고 보존합니다. 창은 열려 있는데 Claude 만 끝난 경우(/exit 등)는 약 2분(두 번 확인) 뒤 정리합니다.
  • 직접 닫은 창은 로그에 직접 닫은 창: … (다시 열려면 claude --resume <ID>) 로 남고 복구 목록에서 빠집니다. 판정 조건: 같은 Herdr 가 계속 떠 있고(살아 있는 창 1개 이상) 그 창의 종료 기록이 killed 일 때만. 판단이 불확실하면 사고로 보고 보존합니다.

9.2 Herdr 를 다시 켰을 때: 복구하기

  1. Herdr 앱이 새로 켜진 것을 키퍼가 감지하면 20초 뒤부터 복구 시도를 시작합니다(10분 동안 30초 간격, 못 끝낸 항목이 있으면 최대 30분, 할 일이 없는 라운드가 3번 이어지면 일찍 끝). 앱은 그대로인데 창 6개 이상이 한꺼번에 죽은 사고도 같은 방식으로 복구합니다.
  2. 자동 복구 대상은 "닫히기 직전에 열려 있던 창"(마지막 확인 시각이 가장 늦은 것에서 10분 이내)만입니다. 더 옛 항목은 복구 목록에 직접 복구 로 남아 버튼으로만 복구됩니다.
  3. 순서: 설치 폴더의 restore-priority.txt 에 적은 공간 이름 순(이 파일은 직접 만들어야 하고, 없으면 공간 구분 없이 진행) → 같은 공간 안에선 최근에 쓴 것 먼저 → 창 주소. 6개씩 묶고 묶음 사이 4초.
  4. 창 종류별 동작:
    • 빈 셸로 되살아난 창 → 그 셸에 claude --resume <ID> (또는 codex resume <ID>) 입력. 창 배치·이름 유지.
    • 끝나 버린 창 → 같은 이름의 공간에 새 탭을 만들어 실행(코어가 켜진 지 120초 뒤부터).
  5. 안전 규칙 — 하나라도 어긋나면 그 창은 건너뜁니다: 같은 대화가 이미 실행 중이 아님 / 대화 파일(.jsonl) 존재 / 시도 3회 미만 / (빈 셸) 같은 탭 + 앞 프로그램이 powershell + AI 없음 + 빈 프롬프트 / (새 탭) 코어 시작 120초 뒤.
  6. 끝나면 LAST-RESTORE.txt 에 결과를 쓰고 알림을 한 번 띄웁니다.

9.3 Herdr 앱 업데이트가 안 되던 이유와 해결 (쉬운 설명)

  • Herdr 는 새 버전을 herdr-app.new 폴더에 받아 두고, 껐다 켤 때 설치 폴더의 이름을 바꿔서 교체합니다.
  • Windows 는 "누군가 작업 위치로 쓰고 있는 폴더"의 이름을 바꾸지 못합니다. 개발 PC 에서는 바로가기의 "시작 위치"가 설치 폴더라서 앱 1개 + 코어 4개 + 터미널 호스트 34개가 그 폴더를 붙잡고 있었습니다(실측). 그래서 교체가 영영 실패했습니다.
  • 세션키퍼는 폴더 이름이 아니라 폴더 안의 파일을 바꿉니다(실행 중인 프로그램 파일도 이름은 바꿀 수 있기 때문).
단계설명
① 전체 백업herdr-app.backup-<버전>-<시각> 폴더(최근 2개 보관)
② 파일별 교체옛 파일을 .old-<시각> 으로 이름 변경 → 새 파일 복사
③ 검증모든 파일의 SHA256 과 --version 확인
④ 실패 시전부 원복(하나라도 틀리면)
⑤ 창 재시작(선택)옛 창에 옛 프로그램으로 종료 신호(app.quit) → 새 프로그램으로 창 기동 → 살아 있는 터미널 수 비교
안전장치업데이트가 창을 끈 뒤 멈추면 키퍼가 20초 뒤 대신 앱을 켭니다. 재시작 중에는 키퍼가 복구 창을 열지도, 기록을 지우지도 않습니다.

15.1 요약

질문답
인터넷으로 보내나요?아니요. 소스 코드(.ps1 .mjs .js .vbs)에서 인터넷 접속 코드(http, Invoke-WebRequest, fetch 등)를 찾았으나 없었습니다(검색으로 확인. 설치 도구의 Node.js 안내 문구에 적힌 주소 글자 https://nodejs.org 는 접속 코드가 아니라 안내 문구입니다). Herdr 앱의 새 버전은 Herdr 자신이 받아 두며, 이 도구는 받아 둔 파일을 옮겨 놓을 뿐입니다.

  4. (앱 업데이트 시) Herdr 설치 폴더 안의 파일(백업 후 교체, 실패 시 원복).
  5. (런처 설치 시에만) 바탕화면·시작 메뉴 바로가기(백업 후 변경).

Claude Code 설정(settings.json 등)과 Codex 설정은 건드리지 않습니다.

15.4 보안상 주의할 점

  • 설치·실행 스크립트는 -ExecutionPolicy Bypass 로 이 스크립트 하나에 한해 실행됩니다. 출처를 모르는 꾸러미는 실행하기 전에 payload 안의 스크립트를 직접 읽어 보세요.
  • 같은 PC 의 다른 사용자 계정 데이터에는 접근하지 않습니다(현재 사용자 폴더만).
  • 공용 PC·타인의 PC 에 설치하려면 소유자의 동의가 필요합니다(18장).
  • 설치 폴더의 접근 권한: 기본 설치 위치(%LOCALAPPDATA%)는 현재 사용자만 쓸 수 있습니다. -InstallDir 로 D: 같은 곳을 쓰면 폴더 권한이 "모든 사용자 쓰기"일 수 있고, 그러면 다른 계정이 키퍼 스크립트를 바꿔치기할 수 있으니 폴더 권한(보안 탭)을 확인하세요.
  • 복구 기록·로그(session-map.json, session-keeper.log 등)에는 대화 ID·폴더 경로·작업 이름이 들어 있으므로 외부에 공유하지 마세요. 저장소에는 올라가지 않도록 .gitignore 에 제외되어 있습니다.
  • 설치 위치는 "세션키퍼 전용 폴더"여야 합니다. 다른 파일이 든 폴더·드라이브 루트는 설치가 거부되고, -RemoveData 제거도 세션키퍼가 만든 파일만 지웁니다.

17. FAQ (자주 묻는 질문)

Q1. 컴퓨터를 켜면 저절로 복구되나요?

아니요. PC 부팅만으로는 아무것도 켜지지 않습니다. Herdr 를 직접 실행하면, 약 1분 안에 키퍼가 켜지고 복구가 시작됩니다.

Q2. AI 가 하던 작업이 그대로 이어지나요?

아닙니다. 대화 기록만 이어집니다. 꺼질 때 진행 중이던 한 번의 작업은 이어지지 않으니, AI 에게 "이어서 해 줘"라고 다시 요청해야 합니다.

Q3. 개인정보가 밖으로 나가나요?

이 도구의 코드에는 인터넷 접속 부분이 없어서 보내지 않습니다(15장). 다만 Claude Code·Codex·Herdr 자체가 하는 통신은 이 도구와 무관하며 각 서비스의 약관·설정을 따릅니다.

Q4. Mac 이나 Linux 에서도 되나요?

아니요. Windows 전용입니다(PowerShell·작업 스케줄러·Windows 프로세스 정보를 사용).

Q5. Herdr 안에서 설치할 수 있는 마켓플레이스인가요?

아니요. Herdr 에는 플러그인 설치 기능이 없습니다(herdr-app 명령에 모드 설치 명령이 없음을 확인). "마켓플레이스"는 Claude Code 용입니다. Herdr 에는 모드 폴더를 복사하는 방식으로 설치됩니다(설치 프로그램이 대신 해 줍니다).

Q6. 설치하면 Herdr 가 닫히나요?

아니요. 설치는 Herdr 를 닫지 않습니다. 앱 업데이트를 적용할 때만(버튼·자동) 창이 잠깐 닫혔다 열리며, 터미널은 유지됩니다.

Q7. Herdr 업데이트가 정말 안전한가요?

전체 백업 → 파일별 교체 → SHA256·버전 검증 → 틀리면 전부 원복 순서입니다. 시험용 별도 Herdr 와 개발 PC 의 실제 Herdr(터미널 26개 유지)에서 성공을 확인했습니다. 단, 모든 PC·모든 버전에서 안전하다고 보장하지는 않습니다(19장).

Q8. 자동 업데이트를 원하지 않아요.

session-keeper.ps1 -Mode Update -Auto Off 또는 세션키퍼 창의 [자동 업데이트] 버튼. 끄면 새 버전이 있어도 알림만 하고, 원할 때 [앱 업데이트] 로 직접 적용합니다.

Q9. 창을 일부러 닫았는데 다시 열리나요?

Herdr 가 켜져 있는 동안 직접 닫은 창은 복구 목록에서 빠지고 되살리지 않습니다. 단, 한 번에 6개 이상을 일부러 닫으면 사고로 보일 수 있어 다음에 되살아날 수 있습니다. 영영 끝낸 작업은 [목록에서 제외] 하세요.

Q10. 오래 꺼 뒀다가 켜도 되나요?

키퍼는 기록을 365일 보존합니다. 다만 Claude Code 자체가 오래된 대화 파일을 지울 수 있는 설정(cleanupPeriodDays, 기본값은 30일로 알려져 있으나 개발 PC 에서 확인한 것은 설정이 없고 78일 전 파일이 남아 있었다는 사실뿐)이 있어, 몇 달 꺼 둘 경우 보장하지 못합니다. 이 도구는 Claude 설정 파일을 건드리지 않습니다. 필요하면 직접 "cleanupPeriodDays": 365 를 설정하세요.

Q11. 여러 PC 에 설치해도 되나요?

기술적으로 PC 마다 설치하면 됩니다. 라이선스는 18장(Apache License 2.0)을 보세요.

Q12. 설치를 되돌릴 수 있나요?

네. 20장. uninstall.ps1 이 설치한 것만 지웁니다. 복구 기록은 기본으로 남깁니다.

Q13. 터미널에서 한글이 깨져 보여요.

화면 표시 문제일 뿐 동작과는 무관합니다. 스크립트는 한글 환경(UTF-8 BOM)에서 시험했습니다.

Q14. 단축키를 바꿨는데 열리지 않아요.

Herdr 가 바뀐 keys.json 을 바로 다시 읽는지는 확인하지 못했습니다. Herdr 를 한 번 껐다 켜 보세요. 그래도 안 되면 Ctrl+Shift+P → mod.open session-keeper 로는 항상 열 수 있고, 창의 [단축키]에서 현재 연결된 키를 확인하거나 [기본값으로]를 눌러 원래대로 돌릴 수 있습니다(5.8).

Q15. 설치 위치를 잘못 정하면 내 파일이 지워지나요?

아니요. 문서 폴더처럼 이미 다른 파일이 들어 있는 폴더나 드라이브 루트는 설치가 거부됩니다. 제거할 때 -RemoveData 를 써도 세션키퍼가 만든 파일(복구 기록·로그 포함)만 지우고, 다른 파일이 있으면 폴더는 그대로 둡니다. 다만 아주 옛 버전(1.1.0 이전)으로 이미 엉뚱한 폴더에 설치했다면, 제거하기 전에 그 폴더에 중요한 파일이 없는지 먼저 확인하세요.
