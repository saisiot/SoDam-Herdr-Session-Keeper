# 대화냥줍 macOS 전환 실행 계획

2026-11-26 · 구현 전 계획 · [원본 구조와 사전 검증](대화냥줍-macOS-설계.md)

**완성된 맥 버전에서 사용자는 Herdr를 열고, 어제 쓰던 Claude Code와 Codex 대화를 원래 프로젝트에서 이어 간다.** 앱만 다시 열었고 대화가 살아 있으면 기존 탭으로 이동한다. 재부팅으로 대화가 끝났으면 마지막에 열려 있던 세션들을 복구한다. 직접 닫은 탭과 복원 여부가 불명확한 탭은 구별해서 보여 준다.

첫 배포 형태는 **맥용 설치 꾸러미 + Herdr 안의 ‘대화냥줍’ 창 + 사용자 계정의 감시기**로 제안한다. 하나의 설치로 원본의 사용 흐름을 재현할 수 있고, 이미 설치된 Herdr가 공간·탭·터미널을 관리한다. 세션 목록만 동작하는 시점은 중간 결과물이다. 재시작 후 복구와 제거까지 검증해야 첫 배포 후보가 된다.

## 1단계 · 요구사항과 결정 근거

| 실제 대화 | 정해진 사항 | 설계에 남긴 결정 |
|---|---|---|
| “대화냥줍 이라는 이름으로 맥용으로 만들고 싶어.” | 제품명은 대화냥줍, 대상은 macOS다. | 화면·명령 팔레트·설치 안내에 같은 이름을 쓴다. |
| “맥버전으로 컨버전 하고 싶어서 그래.” | 기존 Herdr Session Keeper가 기능의 기준이다. | 수동 이어 열기와 자동 복구를 모두 계획에 포함한다. |
| “상세하게 계획을 세워줘.” | 이번 산출물은 구현 전에 검토할 실행 계획이다. | 아래 우선순위와 배포 형태는 제안이며, 실기기 확인이 필요한 조건을 별도로 명시한다. |

**사용자와 문제.** 여러 프로젝트를 오가는 사용자는 대화 제목을 기억해도 그 대화를 열었던 탭을 찾기 어렵다. 재부팅 후에는 어느 창을 되살려야 하는지 기억해야 한다. 반대로, 같은 제목의 세션을 잘못 열거나 이미 살아 있는 대화를 중복 실행하면 복구 자체가 새 문제를 만든다. 따라서 목록을 빨리 보여 주는 것과 자동으로 실행해도 되는지를 서로 다른 기준으로 판단한다.

**범위 판단.** 1차 검증 대상은 현재의 Apple Silicon 맥이다. Herdr 내부 모드를 기본 화면으로 잡되, Dock에서 여는 독립 앱은 후속 제품 선택 사항으로 둔다. Intel 및 이전 macOS 지원 범위는 해당 장비·버전에서 시험한 뒤 정한다. Herdr 자체 업데이트는 맥에서도 재현되는 문제가 있는지 먼저 확인한다. Windows 설치 폴더 잠김을 우회하는 파일 교체 기능은 첫 배포 대상에서 제외한다.

## 2단계 · 제품 요구사항

| 순위 | 사용자 기능 | 완료 기준 |
|---|---|---|
| P0 | 대화 찾기 | 제목·프로젝트 폴더 검색과 AI별 필터가 작동한다. 짧은 대화도 찾아볼 수 있다. 한 도구의 기록을 읽지 못해도 다른 도구의 결과와 오류 원인을 보여 준다. |
| P0 | 원래 작업 이어 열기 | 확실히 열린 세션은 해당 탭으로 이동한다. 닫힌 세션은 원래 폴더에서 정확한 ID로 연다. 작업 폴더가 사라졌으면 원래 경로를 제시하고 위치를 다시 지정한 뒤 재확인한다. |
| P0 | 복구 후보 기억하기 | 창·공간·세션의 관계가 앱 재시작 뒤 남는다. 살아 있는 탭, 직접 닫은 탭, 종료 직전 사라진 탭, 판단 보류가 서로 다른 결과로 나타난다. |
| P0 | 복구 미리보기와 자동 복구 | 항목별 대상·동작·이유를 먼저 볼 수 있다. 동일 조건에서 미리보기와 실행 판단이 일치하고, 두 번 실행해도 같은 대화가 중복 생성되지 않는다. |
| P0 | 설치·업그레이드·제거 | 한 계정에서 관리자 권한 없이 설치한다. 재설치 후 감시기는 한 개이며 이전 설정과 다른 모드는 유지된다. 제거 전후로 AI 원본 기록이 보존된다. |
| P1 | 일상 조작과 진단 | ID·재개 명령 복사, 단일·전체 복구, 대기 목록에서 빼기, 단축키 변경, 복구 결과·인식 저하 원인 확인이 가능하다. 목록 제외 후에도 대화 이력에서 다시 찾을 수 있다. |
| P1 | 원본의 추가 복구 동작 | Herdr가 열린 상태의 집단 종료, 우선 공간, 복구 순서, 감시·예약 소실 안내를 원본 사례와 대조한다. 기능별 검증 결과를 호환표에 표시한다. |
| P2 | 추가 배포 형태 | Intel 지원, 독립 앱, 서명·공증한 일반 배포 패키지, Herdr 업데이트 연동은 요구와 실기기 결과에 따라 각각 결정한다. |

## 4. 구현 순서와 단계별 인수 기준

아래 공수는 **개발자 한 명, 현재 맥과 별도 시험용 Herdr 환경을 쓸 수 있다는 가정의 작업일 추정**이다. 앞 단계의 확인 결과로 다음 범위를 조정한다. 서명·공증, 다른 기종 확보, 공개 배포 일정은 포함하지 않았다.

| 단계 | 선행 | 작업과 산출물 | 통과 기준 | 추정 |
|---|---|---|---|---|
| M0. 격리된 시험 환경 | 없음 | 임시 설정·데이터·상태 폴더, 가짜 Claude JSONL·Codex DB, 호출 인자를 기록하는 가짜 CLI를 만든다. 현재 맥의 도구 버전과 Herdr 앱·코어 주소 분리 가능성을 확인한다. | 실제 대화를 읽지 않고 목록부터 가짜 새 탭 요청까지 재현한다. 앱 설정만 분리해도 코어가 공유되는 경우 별도 테스트 계정에서 실기 시험을 진행한다. | 0.5–1일 |
| M1. 목록과 macOS 모드 | M0 | 경로·오류 진단, 기존 검색·필터, 모드 등록, 복사·새로고침을 연결한다. 설치기의 초안으로 테스트 환경에 모드를 넣는다. | 명령 팔레트로 창을 열어 두 AI의 샘플을 찾는다. 한글·공백 경로, 짧은 기록, 손상 DB, 데이터 없음이 구분된다. 모드 검사와 실제 화면 검사를 모두 통과한다. | 1–2일 |
| M2. 수동 재개 | M1 | 실행 중 세션 식별, 포커스 이동, 새 탭 생성, 누락 폴더 처리, 동시 실행 방지를 구현한다. | 같은 폴더·제목의 두 세션으로 각각 시험한다. 연속 클릭은 한 탭만 만든다. 두 CLI 모두 시험용 실세션에서 원래 ID와 폴더로 재개되는지 확인한다. **여기서 첫 사용 가능한 버전**이 나온다. | 1–2일 |
| M3. 감시와 복구 미리보기 | M2 | 사용자 LaunchAgent가 Herdr 실행 여부를 관찰하고 앱이 떠 있을 때만 스냅샷을 갱신한다. 복구 후보와 이유를 판정해 미리보기에 표시한다. | 앱만 종료·재실행, 감시기만 재실행, 코어 재시작, 컴퓨터 재부팅, 잠자기·깨우기를 구별한다. 미리보기 중 탭 생성·키 입력은 0건이어야 한다. | 2–3일 |
| M4. 자동 복구와 결과 | M3 | 판정 직전에 실제 상태를 다시 읽고 실행한다. 현재 공간·선택 탭을 보존하면서 원래 공간으로 복구하고 결과를 확인한다. 실패·보류·감시 소실 이유를 표시한다. | 살아 있는 대화 중복과 직접 닫은 탭의 자동 재생성이 각각 0건이다. 느린 CLI, 부분 성공, 감시기 재시작 후에도 재시도 상한을 지킨다. | 2–3일 |
| M5. 설치 꾸러미와 배포 후보 | M4 | macOS용 로컬 꾸러미, 설치·제거·문제 해결 안내, 운영체제별 기능표를 만든다. Apple Silicon 시험 계정에서 처음부터 설치하고 이전 버전 위에 재설치한다. | 설치→사용→재부팅→복구→업그레이드→제거를 한 번에 재현한다. 소유하지 않은 모드·키·AI 데이터가 유지된다. Windows 공통 코드 회귀 결과와 미검증 플랫폼을 기록한다. | 1–2일 |

순차 합계는 **7.5–13 작업일**이다. M0가 끝나면 데이터 수집·화면과 macOS 프로세스 조회를 병렬로 개발할 수 있다. 탭 생성은 두 작업의 통합 검증을 거치고, 자동 복구는 미리보기가 같은 사례에서 반복해서 같은 결론을 낸 후에 활성화한다.

### 첫 작업 단위 · Herdr 명령 계약 확인

1. 전용 시험 환경에 같은 제목의 Claude·Codex 세션과 한글·공백 경로를 만든다. 기존 기준선은 `node tests/run-all.mjs lib model fixtures codex`로 재현하고, 알려진 경로 테스트 실패를 따로 기록한다.
2. 코어의 `hc ls/get --json`과 앱의 공간·탭 조회 결과를 대조해 같은 터미널을 가리키는 주소와 PID를 확인한다. 원격 머신에 연결된 공간은 로컬 복원 대상에서 제외한다.
3. 실제 AI 대신 전달받은 인자와 작업 폴더만 출력하는 프로그램으로 수동 재개의 `terminal.open`, 자동 복구의 `tab.new`와 `space.new`를 각각 시험한다. 원래 공간이 사라진 경우, 새 탭이 포커스를 가져간 경우, 앱이 오류 없이 응답했지만 프로세스는 뜨지 않은 경우를 구분한다.
4. 별도 셸에서만 기존 탭 입력을 시험한다. 프로그램 실행 중, 사용자가 명령을 쓰는 중, 빈 프롬프트를 구별할 수 있는지 확인한다. 셸별 판정이 불확실하면 그 경로는 수동 복구로 남긴다.

이 실험의 결과물은 앱·코어 버전, 명령별 입력·응답 예시, 시험 데이터로 다시 실행할 수 있는 검증 코드다. 이 자료가 있으면 감시기와 화면을 서로 다른 작업 단위로 개발해도 같은 계약을 검증할 수 있다.

## 5. 복구 판정과 상태 저장

| 관측한 상황 | 대화냥줍의 동작 |
|---|---|
| 같은 세션이 기존 Herdr 탭에 살아 있음 | 수동으로 선택하면 해당 탭으로 이동한다. 자동 복구 때는 이미 실행 중으로 기록한다. |
| 앱만 다시 열었고 코어가 터미널을 유지함 | 현재 창·터미널을 먼저 조회해 기존 세션을 연결한다. 예전 탭 주소만으로 새 탭을 만들지 않는다. |
| 같은 제목의 두 세션, PID 재사용, Herdr 외부에서 같은 CLI 실행 가능성 | ID와 프로세스 시작 시각·계보 등으로 확인한다. 확정할 수 없으면 ‘판단 보류’와 근거를 표시하고 자동 실행을 건너뛴다. |
| 사용자가 앱 안에서 개별 탭을 닫음 | 직접 닫은 근거가 있으면 자동 대상에서 제외한다. 대화 검색과 수동 재개는 계속 제공한다. |
| 앱 전체 종료 또는 여러 터미널의 동시 소실 | 판단에 쓸 마지막 정상 스냅샷을 유지한다. 한 사고의 자동 후보는 마지막 관측 시각 기준 10분 이내로 고정하고, 오래된 후보는 수동 목록에 둔다. |
| 원래 공간에 빈 셸만 돌아옴 | 탭 정체·셸 상태·입력 줄이 비었음을 검증할 수 있을 때만 그 탭을 쓴다. 작성 중인 명령이 있거나 프롬프트 판독이 불확실하면 보류한다. |
| 새 탭 생성이 필요함 | 자동 생성은 원본의 코어 기동 후 120초 유예를 출발점으로 삼는다. 대상 공간·폴더·기록을 재검사하고, 시작한 세션의 ID를 확인한 뒤 성공으로 기록한다. |

감시 주기 60초, 자동 복구 최대 3회는 원본의 초기값이다. 현재 시각에서 역산하면 며칠 뒤 켠 맥의 복구 후보가 사라지므로, **마지막 정상 관측 시각**을 사용한다. 잠자기나 일시적인 조회 실패로 비어 있는 목록이 돌아와도 마지막 정상 상태를 유지한다. 감시·예약은 대화가 복구될 때 함께 시작되었다고 표시하지 않으며, 종료 전 사용 흔적을 확인할 수 있으면 별도로 안내한다.

상태는 사용자별 `~/Library/Application Support/대화냥줍/` 아래에 둘 계획이다. 저장 대상은 스키마 버전, AI 종류·세션 ID, 프로젝트 경로, 공간·탭·터미널 식별자, 확인 시각, 부팅·프로세스 식별 정보, 복구 시도 횟수·결과다. 대화 전문과 터미널 화면은 상태 파일에 저장하지 않는다. 작성 권한을 사용자로 제한하고, 임시 파일에 쓴 뒤 같은 디렉터리에서 원자적으로 교체한다. 마지막 정상본·버전 마이그레이션을 시험한다. 수동·자동 복구는 같은 실행 경로에서 세션별로 잠그고, 실행 중 중단된 요청은 새 탭 존재 여부부터 대조한다.

## 6. 설치와 운영

- **경로 탐색.** 터미널에서 설치할 때 `herdr-app`, `hc`, Node, Claude, Codex의 경로와 SQLite 읽기 가능 여부를 확인한다. Finder로 연 Herdr와 LaunchAgent는 셸과 PATH가 다를 수 있어 확인한 절대 경로를 사용한다. 한 AI만 설치한 환경도 지원한다.
- **설치 위치.** 모드는 `HERDR_APP_HOME` 또는 기본 `~/.config/herdr-app` 아래에 설치한다. 사용자 LaunchAgent는 `~/Library/LaunchAgents/`에 등록한다. 감시기만 재시작해도 Herdr가 자동으로 열리거나 복구가 두 번 시작되지 않게 한다.
- **단축키.** 명령 팔레트에서 항상 열 수 있게 하고, 기본 조합은 설치된 맥의 Herdr 키 설정을 검사한 뒤 정한다. 다른 모드의 키와 충돌하면 기존 설정을 유지하고 다른 키를 고를 수 있게 한다.
- **업그레이드와 제거.** 설치한 파일·이전 버전을 기록하고 새 버전 검사 후 전환한다. 실패 시 이전 모드와 감시기로 복귀한다. 제거는 등록한 감시기를 내리고 이 꾸러미가 만든 항목만 정리한다. 원본 대화 파일과 다른 모드 설정이 유지되는지 확인한다.

**검증 출발점.** 사전 분석에서 기존 네 묶음은 158개 통과, 1개 실패였다. 실패는 Windows 경로를 macOS에서 읽을 때 마지막 폴더 이름을 추출하는 사례였다. 현재 로컬 도구는 macOS 26.6.2, Herdr 앱 0.1.18, hc 0.1.22, Node 22.22.3이다. 이 버전 조합을 첫 기준으로 삼는다. 원본 전체 시험에는 실제 사용자 세션을 읽는 항목이 있어 자동 시험은 격리된 데이터로 돌린다. Herdr의 모드 검사도 초기화 코드를 실행하므로 검사 모드에서는 외부 명령·감시 시작을 건너뛰게 한다.

**출시 기준.** M5까지 P0 인수 사례를 모두 통과하고, 잘못된 세션 실행·중복 탭·사용자 입력 덮어쓰기·기존 설정 손실이 한 건이라도 발견되면 해당 복구 경로를 수정해 재시험한다. P1 중 검증을 마치지 못한 동작은 기능표에 따로 밝힌다. 공개 배포는 로컬 배포 후보를 검토한 뒤 결정한다.
