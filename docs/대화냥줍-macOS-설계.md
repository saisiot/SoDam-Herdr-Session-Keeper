# 대화냥줍 macOS 버전 설계

2026-11-26 · 설계 초안 · 원본 분석 기준 `2c13300`

**대화냥줍은 “어제 어느 프로젝트에서 무슨 대화를 하다 멈췄지?”라는 질문에서 출발한다.** 첫 버전에서는 맥에 남은 Claude Code와 Codex 대화를 한곳에서 찾고, 원래 작업 폴더에서 이어 연다. 재시작 전의 여러 창을 자동으로 되살리는 기능은 창과 세션의 관계를 검증한 뒤 추가한다.

## 원본은 어떻게 복구하는가

예를 들어 같은 프로젝트에서 Codex 대화 두 개를 켜 두면, 프로젝트 폴더만으로는 어느 대화가 어느 탭에 있었는지 알기 어렵다. 원본은 AI 도구에 남은 기록과 Herdr가 보고하는 창 정보를 따로 읽고, 감시기가 주기적으로 기록한 연결을 복구할 때 사용한다.

| 구성 | 원본의 역할 | 맥 버전에서의 판단 |
|---|---|---|
| [Claude 수집기](../lib/claude.mjs) | 프로젝트별 JSONL에서 세션 ID, 작업 폴더, 제목, 마지막 질문을 읽는다. 실행 중 세션 파일도 조회한다. | 파일 수집기를 재사용한다. 20KB 미만 기록 등을 기본으로 숨기는 기존 규칙이 있으므로 짧은 대화도 찾을 수 있게 한다. |
| [Codex 수집기](../lib/codex.mjs) | 설정 폴더의 `state_N.sqlite`에서 `threads` 테이블을 읽기 전용으로 열고, 존재하는 열을 골라 조회한다. | 수집기를 재사용한다. 현재는 읽기 실패도 빈 배열이 되므로 화면에서 ‘기록 없음’과 ‘읽기 실패’를 구분하게 한다. |
| [창 연결](../lib/join.mjs) · [프로세스 조회](../lib/procs.mjs) | 세션 ID와 프로세스 계보를 창 주소에 연결한다. Codex 제목만 일치하는 경우 최근 기록을 고르는 보조 경로도 있다. | 연결 로직을 살리고 Windows 프로세스 조회를 교체한다. 제목으로만 추정한 결과는 화면에 후보로 표시한다. |
| [목록·동작 CLI](../sessions.mjs) · [수동 복원](../lib/restore.mjs) | 수집 결과를 합치고 이미 열린 대화의 중복 실행을 막는다. Windows에서는 새 탭에 PowerShell을 띄워 재개 명령을 전달한다. | 원래 폴더와 세션 ID를 그대로 사용한다. Herdr의 새 탭에 CLI 실행 인자를 직접 전달하는 경로를 검증한다. |
| [감시기](../session-keeper.ps1) | 약 1분마다 창과 세션의 관계를 저장한다. 직접 닫은 탭과 사고로 사라진 후보를 구분하고 재시작 시 복원한다. | 판정 규칙과 검증 사례를 가져온다. 프로세스 시작 시각, 앱 재실행 감지, 감시기 중복 실행 방지는 macOS에 맞춰 구현한다. |
| [Herdr 모드](../herdr-mod/session-keeper/main.js) · [화면 모델](../herdr-mod/session-keeper/model.js) | 복구 대기·열린 창·꺼진 세션을 검색하고 복구하거나 해당 창으로 이동한다. | 검색·그룹화 로직을 재사용할 수 있다. macOS 설정 경로, 복사 동작, 단축키 충돌 처리는 따로 확인한다. |

원본의 또 다른 큰 기능은 실행 중인 Windows용 Herdr의 업데이트 파일을 교체하고 실패 시 되돌리는 것이다. 대화 기록을 찾고 이어 여는 기능과 독립적이므로 맥 버전 첫 범위에서는 제외하는 안을 제안한다.

## 첫 버전에서 보게 될 화면

**첫 구현 형태로 Herdr 안에서 여는 ‘대화냥줍’ 창을 제안한다.** 이 맥에는 Herdr가 이미 있고, 원본의 화면 모델과 ‘열린 탭으로 이동’하는 동작을 활용할 수 있다. 목록 수집과 창 열기를 분리해 두면 이후 Finder나 Dock에서 실행하는 독립 앱도 같은 수집기를 사용할 수 있다. 독립 앱을 우선할지는 제품 결정으로 열어 둔다.

1. **찾기** — 대화냥줍을 열면 최근 대화가 최신순으로 보인다. 각 행에 AI 종류, 제목, 프로젝트 폴더, 마지막 사용 시각을 표시한다. 제목과 폴더로 검색하고 Claude와 Codex를 걸러 볼 수 있다.
2. **이어 열기** — 이미 열린 탭을 확실히 찾으면 그 탭으로 이동한다. 종료를 확인한 대화는 원래 폴더의 새 탭에서 연다. 상태가 불확실하면 이유와 재개 명령 복사를 제공한다.
3. **예외 처리** — 프로젝트 폴더가 이동했으면 목록에 원래 경로를 보여 주고 새 위치를 선택하게 한다. CLI가 없거나 기록을 읽을 수 없으면 해당 도구와 원인을 표시하고 다른 도구의 목록은 계속 보여 준다.

## 구현 순서와 통과 기준

| 단계 | 구현 | 다음 단계로 넘어갈 조건 |
|---|---|---|
| 1. 대화 목록 | 기존 Node 수집기와 화면 모델을 연결한다. Herdr에서 실행할 Node 경로와 `node:sqlite` 사용 가능 여부를 확인한다. | 가짜 Claude·Codex 기록으로 한글·공백 경로, 짧은 대화, 검색, 기록 읽기 실패를 확인한다. |
| 2. 수동 이어 열기 | `hc ls/get`의 창 정보와 macOS 프로세스의 부모 PID·시작 시각을 대조한다. 확정된 기존 탭은 `agent.focus`로 이동한다. 새 탭은 `terminal.open`에 작업 폴더와 `["claude", "--resume", ID]` 또는 `["codex", "resume", ID]`를 전달한다. | 테스트용 Herdr 공간에서 두 CLI 모두 원래 폴더와 ID로 시작하는지 확인한다. 같은 제목의 두 대화, 이미 열린 대화, 연속 두 번 클릭해도 잘못된 탭이나 중복 실행이 없어야 한다. |
| 3. 재시작 후 복구 | Herdr가 실행 중일 때 창 주소·공간·세션 ID·폴더·마지막 확인 시각을 사용자별 상태 파일에 저장한다. 앱 재시작 시 복구 후보와 판단 이유부터 보여 준다. | 직접 닫은 탭, 앱 전체 종료, 감시기만 재시작, PID 재사용, 코어가 여전히 대화를 유지하는 경우를 구분한다. 전체 종료 직전의 후보만 자동 복구하고 이미 복원한 대화는 건너뛴다. |

자동 복구를 구현할 때는 원본의 정책을 비교 기준으로 삼는다. 마지막 관측 시각에서 10분 안에 있던 창이 기본 자동 대상이고, 새 탭 생성은 코어 시작 후 120초간 기다리며, 재시도는 최대 3회다. 맥의 기본 셸과 사용자별 프롬프트에서 빈 셸을 확실히 판별하기 전에는 기존 탭에 명령을 입력하는 동작을 보류한다.

## 이번에 확인한 범위

- Apple Silicon 맥에서 Herdr 앱 0.1.18, 코어 CLI `hc` 0.1.22, Node 22.22.3, Claude·Codex CLI를 확인했다. 설치된 Herdr의 도움말에는 `terminal.open`, `agent.focus`, 모드 검사 명령이 있다.
- 기존 테스트 네 묶음(`lib`, `model`, `fixtures`, `codex`)에서 158개가 통과했고 1개가 실패했다. 실패는 macOS에서 Windows 경로의 마지막 폴더 이름을 분리하는 사례다. 별도의 임시 Codex DB를 만든 뒤 한글·공백을 포함한 macOS 폴더 이름이 목록에 올바르게 표시되는 것도 확인했다.
- 실제 사용자의 대화 데이터는 검증에 사용하지 않았다. 실제 Herdr 탭 열기, 재부팅 후 복원, 사용자 설정에 모드 설치는 후속 구현의 검증 항목이다.
